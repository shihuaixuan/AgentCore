# 外部对话归档

在 AutoGPT 左侧点击 **对话归档**，打开 `/chat-imports`。同步后的会话和归档都只对导入账号可见，不会写回源应用。

## 将整个目录同步到最近会话

1. 在 **批量同步到最近会话** 中选择来源，浏览器会打开系统目录选择框。
   - **WorkBuddy**：选择 `%USERPROFILE%\.workbuddy\projects`。网页会遍历所选目录及子目录中的 `.jsonl` 会话；也可以只选择其中一个项目目录。
   - **千问办公**：彻底退出客户端后，选择 `%APPDATA%\QwenWorkCN\data`，或包含 `data` 的上一级 `QwenWorkCN`。浏览器会读取本地 `agents.db` 的所有可解析会话，不限于第一页。
2. 选好目录即开始解析和分批同步，不用预览、勾选或先保存归档。保持页面打开，进度条会显示已处理条数，结束后显示**新增、已存在、跳过、失败**。
3. 在左侧 **最近对话** 中打开需要的会话即可继续问。重复选择同一目录可重试失败的会话；已同步的不重复创建，也不覆盖后续回复。同步本身不调用模型。

正常导入时只提交会话标题、问答文字、已有时间和去重标识。会在浏览器内移除用户消息中可识别的系统提示词，保留实际问题和助手回复。不上传原文件、数据库、附件或工具日志。系统不猜测没有明显标记的文字，也不改写此前已经导入的会话。

## 查看归档并继续提问

1. 在 **已保存的对话** 中选中一条，旁边会按用户和助手展示历史消息。已有归档可以直接打开，不需要重新选文件。
2. 点击 **同步到会话**。系统会将历史文字复制为当前组织下的私有会话，在左侧会话列表显示，并自动打开。此时不调用模型；发送新问题后，模型才按普通会话规则读取历史。
3. 同一归档在同一组织中重复同步会打开已有会话，不会重复复制或覆盖后续回复。删除普通会话后可以再次同步。删除归档会删除归档和它的附件，但不删除已同步的会话。

同步只复制消息文字、标题和已有时间，不迁移原文件、附件、工具日志或原客户端的模型设置，也不会重放工具调用。附件仍可从归档下载；需要在追问中使用时，可手动添加到新消息。归档、源客户端和同步后的会话不会双向更新。

## 可选：手动归档 WorkBuddy 会话与附件

1. 打开 **对话归档 → 手动归档会话与附件 → WorkBuddy → 选择会话文件**。
2. 在 Windows 文件选择框地址栏中打开 `%USERPROFILE%\.workbuddy\projects`，进入对应子文件夹，选择一个或多个 `.jsonl` 会话文件。不必运行脚本，也不要选择整个 `.workbuddy` 目录或 `workbuddy.db`。
3. 展开预览，勾选需要的会话。不需要附件时，直接选择 **保存选中对话**；只有勾选会话的标题、问答、时间和用于去重的标识会在确认后提交。
4. 需要附件时，确认 **原目录路径** 是会话引用所在的原始项目目录，再用 **选择附件目录** 授权浏览器读取该目录，并确认将所选目录对应到此原路径。浏览器只提供文件的相对路径，无法区分位于不同位置的同名目录。页面按路径匹配，不会仅凭文件名猜测；请核对匹配到的文件名、相对路径和大小。没找到的文件可以在相应会话的预览下 **手动选取附件**。
5. 附件默认不选。勾选会话及所需附件，再点击 **保存选中对话**；保存后可在归档详情下载。会话 `.jsonl` 原文件、结构化工具日志和未勾选的文件不会自动上传。若对话正文包含本机路径，该路径仍作为正文的一部分保存；匹配用的目录路径和引用不作为独立字段上传。

浏览器不会主动扫描用户目录；只能读取用户授权的文件和目录。目前支持已验证的 WorkBuddy 5.x 文本会话格式；自动匹配只识别部分文本路径和显式文件块，附件格式和存放位置可能因版本而异。页面不会读取客户端会话索引，也不会下载网络链接。只存在于云端或已不在本地的内容无法自动导入。之前生成的规范化 `.json` 文件仍可选择导入，并可手动添加附件。

## 可选：手动归档千问办公会话与附件

1. 完全退出千问办公，然后打开网页的 **对话归档 → 手动归档会话与附件 → 千问办公 → 选择历史目录**。选择前面所述的历史目录，不需要先从客户端导出。
2. 网页在浏览器内只读解析 `agents.db`，列出本地会话。展开预览，勾选要保存的对话，然后点击 **保存选中对话**。数据库原件、工具日志、账号字段和其他目录文件不会上传。仅使用会话标题、问答文本、已有时间以及由本机会话 ID 生成的去重标识。
3. 如果需要原附件，有明确本地路径的引用可通过 **选择附件目录** 匹配；也可以在会话预览中手动选文件。核对并勾选后才会上传附件，不会自动取网盘或远程链接。

已核对 Windows 千问办公 2.1.0 的 `agents.db` 结构。只支持已存入 `chats`、`sub_chats` 和 `messages` 投影表的本地文本；仅在云端或未在本机生成消息投影的会话不一定可见。页面未读取客户端登录状态；批量同步前，请确认选的是要导入的历史目录。发现同目录中有非空写入日志时，请完全退出千问办公后重新选择目录。单个库最大 64 MiB，按更新时间分页读取；批量同步自动读完，手动归档可翻到更早的会话。请使用支持目录选择、Web Worker 和 WebAssembly 的浏览器，如新版 Chrome 或 Edge。

## 运行与边界

- 部署新版本前应用 PostgreSQL 迁移（包括 `20261120120000_continue_imported_chats` 和 `20261120150000_dedupe_native_chat_imports`），重新生成 Prisma 客户端并更新前后端。不要对现有数据执行 `migrate reset`。
- 网页可部署在远程服务器上。文件和目录选择框始终选取打开网页的那台电脑上的文件。导入不再要求 HTTPS 或 `localhost`，但正式环境仍建议使用 HTTPS，保护登录信息及保存时传输的会话与附件。
- 同一账号、同一组织内的最近会话按来源和会话 ID 的摘要去重。之前从仍关联的归档同步过的会话也可去重。旧版 `.json` 导出包的标识可能不同，不能保证和 `.jsonl` 目录导入去重。旧的通义千问归档仍可查看。导入是单向快照，不持续跟踪源会话的编辑、删除或更新。
- 批量同步不限于 25 条，每个请求最多 25 条、4 MiB。单个 WorkBuddy 会话文件最大 32 MiB；单条会话最多 500 条文本消息。无法解析或超出限制的会话会跳过。手动归档最多选择 25 个会话文件，合计不超过 32 MiB，保存的文本合计不超过 4 MiB。部分失败时，已成功的会话或归档会保留。
- 每个 WorkBuddy 或千问办公归档最多 10 个附件，单文件不超过 5 MiB，累计不超过 10 MiB，后端 multipart 请求上限 16 MiB。Vercel 部署按每条会话正文和所选附件合计不超过 4 MiB 提交，为 multipart 请求头留出空间；其他部署网关也可能有更小的限制。附件需通过配置为失败即拒绝的 ClamAV 扫描后才存入 PostgreSQL，只允许归档所有者下载。删除归档会一并删除附件副本，不影响源应用中的原记录。
